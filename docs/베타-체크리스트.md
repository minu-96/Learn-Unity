# 베타 테스트 체크리스트

부원 2~3명에게 30분만 쓰게 하고 관찰합니다. 새 기능을 더하기 전에 이것부터 하세요.

## 준비 (운영진, 한 번만)
- [ ] Firebase 프로젝트를 만들고 `docs/배포-가이드.md`대로 배포했다 (Hosting · Auth · Firestore)
- [ ] Google 로그인을 켜고, 승인된 도메인에 배포 주소를 넣었다
- [ ] `firebase deploy --only firestore:rules`로 규칙을 올렸다
- [ ] 콘솔에서 운영진 계정(이메일/비밀번호)과 `admins/{uid}` 문서를 만들었다
- [ ] GitHub 저장소를 비공개로 바꿨다 (정답 노출 방지)
- [ ] 본인 계정으로 `#admin`에 로그인되는지, 일반 계정은 운영 탭이 안 보이는지 확인했다

## 부원에게 시킬 것 (순서대로)
1. 링크를 열고 Google로 로그인한다
2. 홈의 "진단 시작"으로 3문제를 풀어 본다 (모르면 건너뛰기)
3. 추천된 단계의 개념 설명을 읽고 문제 2개를 푼다
4. 일부러 한 번 틀려 본다 → 오류 메시지가 이해되는가
5. 힌트와 "막혔을 때"를 눌러 본다
6. 정답이라고 생각하는데 틀린 판정이 나오면 "채점이 이상해요"로 신고한다
7. 휴대폰으로도 한 번 열어 본다
8. 다음 날 접속해서 복습 알림이 뜨는지 본다

## 관찰할 것 (옆에서 말없이 보기)
- 홈에서 무엇을 눌러야 할지 바로 알았는가 (3초 이상 망설인 곳)
- 코드를 쓰다가 막힌 곳, 설명이 이해되지 않은 문장
- 조건 칩을 보고 고쳤는가, 무시했는가
- 정답 보기를 누른 시점(몇 번 시도 뒤인가)
- 효과음·축하 연출이 방해됐는가, 도움이 됐는가

## 물어볼 것
1. 지금 무엇을 해야 하는지 항상 알 수 있었나요? (1~5)
2. 문제 난이도는 어땠나요? 입문이 너무 쉽거나 어려웠나요?
3. 채점 결과가 납득됐나요? 억울한 판정이 있었나요?
4. 내일 또 하고 싶나요? 안 한다면 이유는?
5. 하나만 고친다면 무엇인가요?

## 결과 정리
- 오채점 신고 → `tests/play.js`에 해당 코드를 추가해 재발 방지
- 막힌 문제 → 힌트나 개념 설명 보강
- 2주 뒤 운영 화면에서 미활동 비율, 수료 인원, 자력 비율 확인
