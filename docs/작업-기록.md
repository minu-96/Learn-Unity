# 작업 기록

## 배경
처음에는 Claude 아티팩트(단일 HTML) 한 장으로 만든 학습 도구였다. 동아리 부원에게 배포해 스터디 도구로 쓰려면 구글 로그인, 부원별 진도 확인, 운영진 접속, 입문·기초·심화 구분이 필요했고, 아티팩트로는 이를 안전하게 만들 수 없어서(코드가 공개되어 비밀번호 검사 불가, API 키 보관 불가, 사용자가 Claude 계정을 가져야 함) 독립 웹앱으로 옮겼다.

## 결정 사항
| 항목 | 결정 | 이유 |
|---|---|---|
| 배포 도구 | Firebase 하나 (Hosting + Auth + Firestore) | 호스팅·로그인·DB를 한 곳에서 해결, 명령 한 줄 배포 |
| 요금제 | Spark(무료, 카드 불필요) | 소규모 동아리면 충분, 한도를 넘으면 청구 대신 중단 |
| AI | 이번 단계에서는 사용하지 않음 | 사용량 부담 최소화. 채점·힌트·복습은 전부 로컬 |
| 로그인 | 부원 = Google, 운영진 = 아이디/비밀번호 | 운영진 아이디는 `아이디@admin.learn-unity.example` 이메일로 Firebase에 등록 |
| 설정이 없을 때 | 게스트 모드(localStorage만) | Firebase 없이도 로컬에서 바로 실행·테스트 가능 |

## 이전 버전(아티팩트) 이력
- v1/v2: 객관식 퀴즈 → 사용자 요구로 폐기
- v3: 모든 문제를 코드 작성형으로 전환. 12개 분야, 90문제, 조건별 채점, 복습, 연습 과제, AI 튜터/판정(아티팩트의 Claude 호출)
- v4: 채점기를 JavaScript 변환 방식에서 **C# 부분집합 해석기**로 교체(eval·워커 불필요), 맞는 풀이를 틀리게 보는 규칙 약 30개 완화, Lv.3 설명을 증상 중심으로 개선, 학생 풀이 59개·코드 모양 변형 테스트 추가

## 이번 작업 (웹앱 이관)
1. 저장소 구조로 소스 이관: 엔진·문제·UI를 `public/`로, 검증 스크립트를 `tests/`로 옮기고 경로 수정. 기존 검증 결과 유지(90문제 `bad 0`, 학생 풀이 `0 / 59`, 변형 `0`).
2. 학습 구간: `tiers.js`에 30개 단계를 입문(21문제)·기초(30)·심화(39)로 매핑하고, 진행 요약(`summarize`)과 수료 기준(80% 해결 + 자력 60%)을 추가.
3. 저장소 어댑터(`store.js`): Google 로그인, 운영진 로그인, Firestore 저장. 변경된 문서만 쓰고 4초 단위로 묶어 쓰기 횟수를 줄임. 다른 기기 기록과는 문제별로 병합(해결 우선, 채점 횟수는 큰 값).
4. 화면: 로그인(게스트 선택 가능), 내 기록(구간별 진도·수료 상태·분야별 현황·다시 볼 문제), 운영진 대시보드(부원 현황·미활동 필터·CSV·막히는 문제·신고 처리).
5. AI 제거에 따른 대체: 튜터 영역을 "막혔을 때" 안내와 **채점 오류 신고** 버튼으로 교체, 개념 사전은 직접 정리해 추가.
6. 보안 규칙: 부원은 본인 문서만, 운영진은 요약 문서(`users/{uid}`)와 신고만 읽음. 풀이 기록·작성 중인 코드(`users/{uid}/data/*`)는 본인 전용. `admins/{uid}` 문서는 콘솔에서만 생성.

## 아직 검증하지 못한 것
- **실제 Firebase 연동**: 테스트는 가짜 Firebase로 했다. 실제 Google 로그인 팝업, Firestore 응답, 호스팅 배포는 프로젝트 설정 후 확인이 필요하다.
- **보안 규칙**: `firestore.rules`는 에뮬레이터로 실행해 보지 못했다. 배포 후 (1) 부원이 남의 문서를 읽을 수 없는지 (2) 운영진 계정만 `users`를 읽는지 (3) 일반 부원이 `admins`에 쓸 수 없는지 확인할 것.
- 실제 부원의 사용: 맞는 풀이가 틀리게 채점되는 사례는 베타 테스트에서 나올 가능성이 가장 크다. 신고된 코드는 `tests/play.js`에 추가한다.
