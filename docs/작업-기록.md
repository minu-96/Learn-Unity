# 작업 기록

## 배경
처음에는 Claude 아티팩트(단일 HTML) 한 장으로 만든 학습 도구였다. 동아리 부원에게 배포해 스터디 도구로 쓰려면 구글 로그인, 부원별 진도 확인, 운영진 접속, 입문·기초·심화 구분이 필요했고, 아티팩트로는 이를 안전하게 만들 수 없어서(코드가 공개되어 비밀번호 검사 불가, API 키 보관 불가, 사용자가 Claude 계정을 가져야 함) 독립 웹앱으로 옮겼다.

## 결정 사항
| 항목 | 결정 | 이유 |
|---|---|---|
| 배포 도구 | Firebase 하나 (Hosting + Auth + Firestore) | 호스팅·로그인·DB를 한 곳에서 해결, 명령 한 줄 배포 |
| 요금제 | Spark(무료, 카드 불필요) | 소규모 동아리면 충분, 한도를 넘으면 청구 대신 중단 |
| AI | 이번 단계에서는 사용하지 않음 | 사용량 부담 최소화. 채점·힌트·복습은 전부 로컬 |
| 로그인 | 부원 = Google, 운영진 = 아이디/비밀번호 | 운영진 아이디는 `아이디@admin.learn-unity.example` 이메일로 Firebase에 등록 |
| 설정이 없을 때 | 게스트 모드(localStorage만) | Firebase 없이도 로컬에서 바로 실행·테스트 가능 |

## 이전 버전(아티팩트) 이력
- v1/v2: 객관식 퀴즈 → 사용자 요구로 폐기
- v3: 모든 문제를 코드 작성형으로 전환. 12개 분야, 90문제, 조건별 채점, 복습, 연습 과제, AI 튜터/판정(아티팩트의 Claude 호출)
- v4: 채점기를 JavaScript 변환 방식에서 **C# 부분집합 해석기**로 교체(eval·워커 불필요), 맞는 풀이를 틀리게 보는 규칙 약 30개 완화, Lv.3 설명을 증상 중심으로 개선, 학생 풀이 59개·코드 모양 변형 테스트 추가

## 이번 작업 (웹앱 이관)
1. 저장소 구조로 소스 이관: 엔진·문제·UI를 `public/`로, 검증 스크립트를 `tests/`로 옮기고 경로 수정. 기존 검증 결과 유지(90문제 `bad 0`, 학생 풀이 `0 / 59`, 변형 `0`).
2. 학습 구간: `tiers.js`에 30개 단계를 입문(21문제)·기초(30)·심화(39)로 매핑하고, 진행 요약(`summarize`)과 수료 기준(80% 해결 + 자력 60%)을 추가.
3. 저장소 어댑터(`store.js`): Google 로그인, 운영진 로그인, Firestore 저장. 변경된 문서만 쓰고 4초 단위로 묶어 쓰기 횟수를 줄임. 다른 기기 기록과는 문제별로 병합(해결 우선, 채점 횟수는 큰 값).
4. 화면: 로그인(게스트 선택 가능), 내 기록(구간별 진도·수료 상태·분야별 현황·다시 볼 문제), 운영진 대시보드(부원 현황·미활동 필터·CSV·막히는 문제·신고 처리).
5. AI 제거에 따른 대체: 튜터 영역을 "막혔을 때" 안내와 **채점 오류 신고** 버튼으로 교체, 개념 사전은 직접 정리해 추가.
6. 보안 규칙: 부원은 본인 문서만, 운영진은 요약 문서(`users/{uid}`)와 신고만 읽음. 풀이 기록·작성 중인 코드(`users/{uid}/data/*`)는 본인 전용. `admins/{uid}` 문서는 콘솔에서만 생성.

## 아직 검증하지 못한 것
- **실제 Firebase 연동**: 테스트는 가짜 Firebase로 했다. 실제 Google 로그인 팝업, Firestore 응답, 호스팅 배포는 프로젝트 설정 후 확인이 필요하다.
- **보안 규칙**: `firestore.rules`는 에뮬레이터로 실행해 보지 못했다. 배포 후 (1) 부원이 남의 문서를 읽을 수 없는지 (2) 운영진 계정만 `users`를 읽는지 (3) 일반 부원이 `admins`에 쓸 수 없는지 확인할 것.
- 실제 부원의 사용: 맞는 풀이가 틀리게 채점되는 사례는 베타 테스트에서 나올 가능성이 가장 크다. 신고된 코드는 `tests/play.js`에 추가한다.

## UX 개편 (학습 중심)
기존에는 분야 탭에서 문제 목록을 고르는 구조라 "지금 무엇을 해야 하는지"가 보이지 않았다. 학습 흐름 기준으로 다시 짰다.
- **오늘(홈)**: 오늘 목표(하루 3문제) 링, 연속 일수, 최근 7일 막대, 복습 시작, 이어서 풀 다음 문제, 입문/기초/심화 진행도.
- **학습 지도 → 단계 화면**: 30개 단계를 입문/기초/심화로 묶어 보여 주고, 단계마다 개념 설명(핵심 3줄·예제)을 읽은 뒤 문제를 푼다.
- **문제 화면**: 좌측 설명·목표·힌트, 우측 편집기. 조건 칩이 코드를 쓰는 동안 실시간으로 충족 여부를 보여 준다. 막히면 "막혔을 때" 안내와 채점 오류 신고. 이전/다음 문제 이동.
- **정답 후**: 내 코드와 모범 코드 비교, 왜 그렇게 되는지, 관련 개념, 한 줄 회고(내 메모), 체감 난이도 선택.
- **복습**: 라이트너 상자(1·3·7·16·35일)로 복습 대상이 자동 계산되고, 복습 시작 한 번으로 이어서 푼다.
- **개념 사전/내 기록**: 푼 개념이 쌓이고, 내 메모를 모아 본다. 용어는 누르면 뜻이 뜬다.
- 저장 항목에 `act`(일별 활동), `notes`(회고)가 추가됐고 기기 간 병합 규칙을 정했다(act는 큰 값, notes는 나중 시각).
- 채점 엔진은 그대로다. 전체 화면 순회 테스트(30단계 + 90문제)에서 오류가 없었고, 모든 모범 답안에서 조건 칩이 전부 충족으로 표시된다.

## 재미·완성도 보강
첫 평가에서 나온 약점을 고쳤다.
- **분위기**: 효과음(WebAudio 합성, 음원 파일 없음, ♪ 버튼으로 끔), 정답 시 색종이, 경험치(+XP)·레벨 업·배지 알림, 헤더 레벨 칩, 정답 영역 등장 애니메이션. `prefers-reduced-motion`이면 애니메이션과 색종이를 끈다.
- **코드 편집기**: 구문 색(키워드·타입·함수·문자열·숫자·주석·어트리뷰트). 투명 textarea 뒤에 같은 글자를 색칠해 겹치는 방식이라 입력 동작은 그대로다. 코드 비교·모범 코드·예제에도 적용.
- **시작 위치 진단**: 처음 접속하면 입문·기초·심화 각 1문제(3문제)로 시작 구간을 추천한다. 건너뛰기 가능. 결과는 `S.diag`에 저장하고 추천 문제가 그 구간부터 시작한다.
- **주차 과제 + 팀 진도**: 운영진이 단계를 골라 마감일과 함께 지정(`config/weekly`). 부원 홈에 진행률·D-day 카드, 학습 지도에 "과제" 표시. 운영 표에 과제 열·미완료 필터·CSV 열. 규칙은 `firestore.rules`에 `config` 추가(읽기 로그인, 쓰기 운영진).
- **정답 노출**: 정적 사이트의 한계라 코드로 막지 않고, 저장소 비공개 + 자력 지표로 대응하도록 `docs/운영-가이드.md`에 정리했다.
- **베타**: `docs/베타-체크리스트.md` 추가.
- 테스트: `tests/fx.js`(진단·과제·배지·구문 색·모바일) 추가.
- 아직 못 한 것: 운영진이 코드 없이 문제를 추가하는 기능, 서버 채점.

## 미리보기 (아티팩트)
Firebase 설정 전에 화면을 확인할 수 있도록 `preview/build.js`가 웹앱을 단일 HTML로 묶는다. Firebase 대신 `tests/fake-firebase.js`를 넣고, `preview/seed.js`가 가상 부원 6명·신고 1건·운영진 계정(admin / pw1234)을 심는다. 실제 서비스(`public/`)에는 포함되지 않는다.
- 실행: `node preview/build.js 출력.html`
- 미리보기에서는 CSV 내려받기가 동작하지 않는다(아티팩트가 다운로드를 막음). 배포한 사이트에서는 동작한다.
- 이 과정에서 고친 것: 운영진 로그인 뒤 로그아웃하면 로그인 화면으로 돌아가도록 수정(페이지 새로고침 대신 화면 전환), 기록이 없는 부원도 구간별 전체 문제 수를 표시.

## 4단계 개편 (입문·기초·응용·심화)
- 기존 입문(변수·if를 아는 사람 기준)은 **기초**로 내리고, 코딩을 처음 하는 사람을 위한 **입문**을 새로 만들었다. 새 분야 `start`(코딩 첫걸음) 5단계 × 3문제 = 15문제, 전부 유니티 없이 C# 메서드를 완성하는 방식이라 여러 입력으로 실행해 채점한다.
- 기존 기초·심화 69문제는 **응용**(36)과 **심화**(33)로 나눴다. 디버깅 2와 게임 주스 1은 응용, 나머지 심화는 연출·설계·최적화 위주로 남겼다.
- 시작 위치 진단을 4문제로 늘렸다. 3구간 시절 저장된 진단 결과는 `migDiag()`가 새 구간으로 옮긴다(옛 입문 → 기초, 옛 기초 → 응용).
- 응용 수료 배지(배지 12개), 운영진 표와 CSV에 응용 열을 추가했다. 문제 난이도 라벨 `Lv.2`는 단계 이름과 겹치지 않게 "보통"으로 바꿨다.
- 운영진 표의 부원 요약(`summary.tier`)은 각 부원이 다음에 접속해 저장할 때 새 구간 기준으로 갱신된다.

## 문제 사전
- 학습 지도에 없는 추가 문제 모음. (분야, 단계, 레벨)마다 3문제가 한 세트이고, 같은 분야·단계·레벨의 학습 지도 문제를 하나만 풀어도 그 세트가 열린다.
- 현재 입문 5단계 × 3레벨 × 3문제 = 45문제(x1~x45), 기초 7단계 × 3레벨 × 3문제 = 63문제(x46~x108, `p_bank2.js`). 진도·수료·진단에는 들어가지 않고, 경험치·복습·개념 사전에는 반영된다.
- 코드: `public/js/p_bank.js`(문제), `public/js/bank.js`(화면·열림 판정). 테스트: `tests/check.js`(세트당 3문제 검사), `tests/bank.js`.
- 다음 단계: 기초·응용·심화 단계에도 세트 추가.
